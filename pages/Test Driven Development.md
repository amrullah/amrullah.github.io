- # The harms of Tech debt
- **increased cost of change** → increased time to adapt to changes in market → Losing competitive edge
- Friction in forming a coherent mental model of the existing software context → slow feature development → increased cost of change
- Low developer confidence upon the codebase → very high testing time → increased cost of change
- low code safety → bugs leaked to production → unreliable software → customer satisfaction lowered → customer attrition
- Low developer confidence upon the codebase → Low developer job satisfaction
- bugs leaked to production → much time spent in firefighting → Low developer job satisfaction
- Low developer job satisfaction → Developer attrition → Resources spent in recruiting new developers, bringing them upto the speed of the existing context (which anyways is slow)
- tech debt begets more tech debt → All the above mentioned problems keep worsening over time (Broken Window Theory)

- # Benefits
- at least Keeps tech debt in check, at best helps tackle it in it's embryonic stages, when it's easy to tackle.
- helps make drastic changes to the design decisions (low level design)
- makes high level design changes significantly easier.
- more feature shipping velocity
- increased developer psychological safety and job satisfaction
- ushers a culture of quick experimentation, AB testing etc, which product managers can leverage to study customer behavior or collect some other intelligence before making key strategic product decisions
- Helps react to market changes quicker and gain a competitive edge
